Plugin Architecture

Every integration follows the same modular pattern:

  1. Service file — handles API communication
  2. Realtime tool — GeordieDaz can call it mid-conversation by voice
  3. UI card — shows live data in the Connected Services panel
  4. Memory integration — remembers your preferences across sessions

Memory Persistence — Architecture

GeordieDaz uses a 3-tier memory system that persists permanently across sessions, devices, and time:

TierStorageWhatPersistence
Working MemoryRedisLast 20 conversation turns24hr TTL, survives restarts
Semantic MemoryPostgreSQL + pgvectorExtracted facts (name, car, preferences)Permanent — forever
Episodic MemoryPostgreSQLSession summariesPermanent — forever

Cross-Session Example

Session 1: User says "I drive a red Ferrari" → fact stored permanently in PostgreSQL with vector embedding

Session 2 (days later, different device): User says "What car do I drive?" → vector search finds the fact → GeordieDaz responds: "You drive a red Ferrari, bonny lad!"
